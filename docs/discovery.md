# 需求访谈

## 已知情况

- 用户希望治理同一台机器上开发多个项目时的端口混乱。
- Agent 启动服务后，用户可能不知道其端口，或过一段时间忘记。
- 用户观察到 Agent 关闭后，有时服务端口也不再可用；具体原因尚未核实。
- 多个项目的端口难以记忆。
- 用户希望了解是否已有相关开源方案。

## 第一轮已确认

1. 第一版先服务用户自己；具体运行环境尚待确认。
2. 首要价值是一眼看到各项目正在运行的服务及访问地址。
3. 区分需要保留的开发服务和临时服务，结束对话不等于结束所有服务；默认类别与停止时机尚待确认。
4. 接受让 Agent 和用户通过统一命令启动服务；这不表示已排除自动发现或项目配置。

## 开源方案初查

核查日期：2026-10-09。依据公共 README，尚未安装或运行验证；以下并非穷尽市场调研。

| 方案 | 已确认能力 | 资料边界 |
| --- | --- | --- |
| [Portless](https://github.com/vercel-labs/portless/blob/main/README.md) | 面向人和 Agent；自动分配端口、稳定 localhost 域名、活动路由列表、monorepo/worktree 命名 | 常驻 proxy 不等于应用常驻；Ctrl+C 会结束应用进程树。未确认可自动发现全机服务并识别项目 |
| [Process Compose](https://github.com/F1bonacc1/process-compose/blob/main/README.md) | 配置式多进程管理、命名空间、启停、恢复、日志、健康检查、daemon 模式、MCP | 未确认自动端口发现、自动端口分配或稳定项目域名；Agent 退出后的表现需实测 |
| [PM2](https://github.com/Unitech/pm2/blob/master/README.md) | 守护运行、进程列表、日志、启停、namespace、保存进程列表与开机启动 | 未确认自动端口发现、稳定项目 URL 或 worktree 归属；需主动通过 PM2 启动 |

## 第二轮已确认

用户答复：全部按照建议来。

1. 第一版覆盖 macOS 本机直接运行的服务；Docker 和远程开发暂不纳入。
2. 使用浏览器面板，按项目/工作区显示服务名称、状态、地址，支持点击打开。
3. 同仓库的不同 Git worktree 分别展示，注明共同仓库。
4. 第一版保证保留服务在 Agent 退出后继续运行；普通前端预览、后端 API 默认保留，临时服务显式标记。

## 第三轮已确认

用户答复：全部按照建议。

1. 发现已有监听服务；无法确定归属时显示“未归属”，允许手动关联工作区。关联记录不代表接管进程；首版只管理通过统一入口启动的服务。
2. 面板提供单个受管服务的停止、重启和最近日志；启动新服务使用统一命令，首版不做网页编辑启动配置。
3. 保留服务意外退出后有限次重试，连续失败显示错误；机器重启后保留记录、手动启动。临时服务在统一命令结束或用户停止时退出，首版不自动判断 Agent 会话结束。
4. 同工作区同名服务重复启动时返回已有服务及地址；更换启动命令需明确重启。不同 worktree 的服务独立。
5. 优先实测 Process Compose 或 PM2 的常驻与启停，再补工作区归属和浏览器面板；Portless 为访问入口候选。尚未选择具体依赖。

## 第四轮已确认

用户答复：全部按照建议。

1. 启动必需项为服务名称与启动命令；工作区从当前目录识别。返回状态、工作区、实际地址，支持 JSON 输出。通过项目内 AGENTS.md 指导 Agent 使用，首版不要求 MCP。
2. 对能接受外部端口配置的服务选择空闲端口；端口写死发生冲突时报告冲突及已知占用者。固定域名非首版必需项。
3. 区分启动中、运行中、已停止、失败；确认监听后显示运行中，说明地址是否已验证可连接。地址未知时明确展示并允许补充；可连接不等于业务健康。
4. 验收覆盖两个项目各自前后端、Agent 退出、两个 worktree、重复启动和启停日志、已有服务发现及重启后的历史记录。
