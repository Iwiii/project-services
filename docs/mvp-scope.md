# 首版范围

状态：四轮范围决策已获用户确认；本汇总等待最终共同理解确认。确认后先进行技术验证。

## 目标

让用户在一台 macOS 机器上，一眼找到各开发工作区的服务、运行状态和实际访问地址；普通开发服务在 Agent 退出后仍继续运行。

第一版先服务用户自己，覆盖本机直接运行的服务。

## 使用流程

1. 用户或 Agent 在工作区内通过统一命令提供服务名称和启动命令，普通服务默认保留，临时服务显式标记。
2. 工具识别工作区，启动或返回已有服务，输出状态、工作区和实际地址；支持 JSON 输出供 Agent 使用。
3. 用户打开浏览器面板，按工作区查看服务、状态和地址，打开地址、查看最近日志或停止、重启受管服务。
4. Agent 结束后保留服务继续运行；临时服务随统一命令结束或手动停止而退出。

通过项目内 AGENTS.md 说明统一命令的使用方式。

## 归属与管理边界

- 同仓库不同 worktree 分别展示，并注明共同仓库。
- 同工作区同名服务重复启动返回已有服务；更换启动命令需要明确重启。
- 发现未经统一入口启动的监听服务；归属不明时显示未归属，允许手动关联工作区。
- 手动关联仅建立记录，不接管进程；启停和日志管理面向受管服务。

## 端口与状态

- 能接受外部端口配置的服务自动选择空闲端口；端口写死发生冲突时报告冲突及已知占用者。
- 面板展示实际地址，未知时明确标识并允许补充；固定域名不是首版必需项。
- 展示启动中、运行中、已停止、失败；确认监听后才标为运行中。
- 标明地址是否已验证可连接，可连接不代表业务健康。

## 生命周期

- 普通前端预览和后端 API 默认保留，Agent 退出不停止服务。
- 保留服务意外退出后有限次重试，连续失败显示错误；用户主动停止不触发自动恢复。
- 机器重启后保留记录，服务手动启动。
- 临时服务在统一命令结束或用户停止时退出，首版不自动判断 Agent 会话结束。

## 首版不纳入

Docker、远程开发、其他操作系统、网页编辑启动配置、强制固定域名、MCP 接入以及接管任意已有进程。

## 验收场景

1. 两个项目各启动前端和后端，面板正确展示工作区、服务和可打开的地址。
2. 关闭 Agent 后保留服务仍可访问；临时服务随统一命令结束而停止。
3. 同一仓库的两个 worktree 各自运行同名服务，归属和操作互不混淆。
4. 重复启动返回已有实例；停止、重启和日志查看有效。
5. 绕过统一入口启动的服务仍能被发现，无法确定归属时显示未归属；机器重启后历史记录仍在。

## 下一阶段：验证后选型

优先验证 Process Compose 或 PM2 的常驻、启停和有限重试能力；Portless 作为访问入口候选，尚未选定依赖。

验证需覆盖真实 Agent 退出、子进程清理、实际监听地址识别、worktree 隔离和并发重复启动。根据结果明确哪些能力可以复用、哪些需要自行实现，再形成技术方案。
